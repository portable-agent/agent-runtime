# Памятка по agent-runtime

## Назначение

Сервис переводит пользовательский текст в предложение действия. Он stateless: не имеет своей БД
и не исполняет созданное предложение.

## Границы

- `controllers` принимает HTTP и вызывает один сервис;
- `services` содержит сценарий приложения;
- `repositories` содержит только адаптеры к внешней AI-модели и policy-сервису;
- `models` не знает о FastAPI;
- `schemas` описывает внешний HTTP-контракт;
- `config` собирает зависимости;
- `main.py` создаёт приложение.

Контроллер не должен содержать бизнес-логику. Репозиторий не должен решать, можно ли исполнять
действие. В сервис нельзя добавлять хранение состояния между запросами.

## Простые имена

Используй короткий английский уровня A2–B1: `UserContext`, `ActionPlan`, `ModelReply`, `get_risk`.
Не используй редкие слова, сокращения без расшифровки и абстрактные имена вроде `Manager`,
`Processor`, `Facade`. Термины внешнего контракта (`proposal`, `connector`, `tenant`) сохраняй,
пока контракт не изменён отдельным решением.

## Как менять код

1. Сначала добавь тест, который падает по ожидаемой причине.
2. Напиши минимальный код для прохождения теста.
3. Упрости код, не меняя поведение.
4. Запусти все проверки из README.
5. Если меняются границы, API или команды, обнови README, `docs/` и `catalog-info.yaml`.

Не добавляй бизнес-правила по догадке. Остановись и запроси решение владельца продукта для:

- списка разрешённых действий;
- уровней риска и правил подтверждения;
- выбора AI-модели и policy-сервиса;
- формата ошибок и retry;
- правил работы с персональными данными.

## Definition of Done

- тест написан до рабочего кода;
- Ruff, format, strict mypy и pytest зелёные;
- покрытие сервисного слоя не ниже 90%;
- `mkdocs build --strict` проходит;
- документация отражает фактический код;
- новые зависимости обоснованы и зафиксированы в `uv.lock`.
